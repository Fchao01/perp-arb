# RH / LIGHTER 全市场只读筛选器

入口是 `tools/market_screener.py`，网页文件在 `tools/screener_web/`。独立于交易引擎：
不读取 `.env`，不使用账户私钥、Signer SDK 或交易接口，不启动实盘策略。

## 启动采集与网页

在项目根目录、现有 Python 虚拟环境中运行。依赖与项目基础 `requirements.txt` 相同。

先确认共同活跃永续市场：

```bash
python3 tools/market_screener.py list
```

终端一，采集 72 小时（第一段 24 小时训练，后续样本外验证）：

```bash
python3 -u tools/market_screener.py collect --hours 72 --notional 300
```

终端二，打开只读网页服务：

```bash
python3 -u tools/market_screener.py serve --input logs/screener --port 8765
```

本机浏览器打开 `http://127.0.0.1:8765`。网页默认每 5 秒更新状态。
如果采集在远程服务器，从自己电脑建立 SSH 转发：

```bash
ssh -N -L 8765:127.0.0.1:8765 用户名@服务器地址
```

然后仍在自己电脑打开 `http://127.0.0.1:8765`。服务默认仅绑定回环地址；无需开放公网端口。
网页只是读取数据，不启动、停止或修改采集，不提供交易按钮。

后台运行示例：

```bash
mkdir -p logs/screener
nohup python3 -u tools/market_screener.py collect --hours 72 --notional 300 > logs/screener/collector.log 2>&1 &
nohup python3 -u tools/market_screener.py serve --input logs/screener --port 8765 > logs/screener/web.log 2>&1 &
```

采集按 Ctrl-C / SIGTERM 正常退出，已完成批次保留。每次运行创建新的独立目录，不覆盖旧会话。
网页传入父目录时自动选择最新会话；如要固定查看旧会话，`--input` 指向具体运行目录。

## 网页看什么

- **实时盘口**：采集开始即可查看每个市场的目标数量深度价差、RH 溢价和探测状态。
- **验证排行**：训练结束后累计样本外数据。默认至少 24 小时样本外数据和 5 次影子往返，
  且深度、延迟有效覆盖不低于 90%，训练深度覆盖不低于 80%，才可能显示“样本外正值”。
- **市场详情**：冻结训练中线、样本外基差曲线、影子已平仓累计值、单次往返、持有时间、超时退出。
- **方法与假设**：显示本轮成本、金额、延迟和训练配置。
- **导出排行**：下载当前分析的 CSV。

“训练中”“验证不足”是正常状态，不会因为几十秒的采样就给出“稳定盈利”结论。
即使显示正值，仍只是只读研究候选，未核验合约、资金费和真实成交率。

## 采集原理和数据

脚本通过两边公共 GET `orderBooks?filter=perp` 取共同活跃永续市场。
只接受精确相同 symbol；发现已知 multiplier、settlement 等元数据不一致就排除。
同名市场的指数、抵押品和经济含义可能仍不同，不能自动视为已经审核通过。
市场交集和基础费率固定在启动时，不在运行中自动纳入新上市市场。

公共 WebSocket 持续更新本地盘口，并检测 nonce 连续性；断线、跳号、交叉盘口会使缓存失效。
每个连接默认订阅 25 个市场。没有为每个市场轮询 REST，避免大量接口调用。

默认每 **5 秒**发起一批探测，对每个市场：

1. 保存双方最多各 10 档买卖深度及本地接收年龄、nonce 和原始服务器时间字段。
2. 按 $300 等值买入预算和双方共同数量精度确定数量；买卖腿使用相同 base 数量。
3. **350ms 后**再次保存盘口，仍按原数量重新计算报价，不能因价格变了偷偷缩量。
4. 记录实际探测间隔。超出目标 100ms、盘口本地更新年龄超过 1000ms、期间断线重连的观测会被标记无效。

这不是完整逐 tick 档案，而是带原始深度的定时延迟探测。短于采样间隔的机会可能被漏掉。
安静市场长时间没有盘口变化也可能被保守地标为不可观测，不能据此断定交易所宕机。
本地接收年龄不是源行情延迟；原始服务器时间未被假设为与本机完全同步。

运行目录示例：

```text
logs/screener/20261025T000000Z-xxxxxxxx/
  manifest.json                 参数、费率、市场映射、原始元数据
  live.json                     网页快照、已完成文件的字节检查点
  probes-20261025.jsonl.gz       UTC 按日压缩的延迟探测
  latest_analysis.json           最近完整分析的指针
  analysis-.../
    report.json                 网页分析与详细数据
    ranking.csv                 市场排行
    cycles.csv                  全部影子往返记录
```

gzip 每批写成独立完整成员。离线分析读取检查点内的数据，因此可与采集同时运行。
按 49 个市场、5 秒间隔计算，每天约 85 万次探测；存储大小取决于盘口，可能达到数百 MB/天或更多。
可用 `--interval-ms 10000` 降低采样频率，350ms 探测延迟不变。查看实际目录大小后决定保留天数。

## 离线分析与模型

采集默认每小时自动分析，正常退出也会分析。也可以手动执行：

```bash
python3 tools/market_screener.py analyze \
  --input logs/screener/具体运行目录 \
  --notional 300 --train-hours 24 --min-test-hours 24
```

每次分析新建目录，生成完成后才更新网页指针。采集中的原始数据不会被修改。

训练只使用运行开始后前 `--train-hours` 小时：

- 用中间价溢价的中位数估计基差中线。
- 按目标金额计算两个方向的费用后深度价差。
- 每方向门槛取训练价差 90% 分位与“对应中线 + 最小偏离带宽”的较大值。
- 带宽默认 `--min-band-bps 2`。中线较大时，反向方向门槛可以为负；只看一次跨市场价差不能判断整个往返。
- 阈值在样本外阶段冻结，未来数据不参与拟合。

影子模型每个市场最多持有一组假想的相反库存：

1. 在当时盘口决定是否进入，不能看到延迟后仍赚钱才选择进入。
2. 假设两腿均按 350ms 后可见 VWAP **完整成交**，即使优势已经消失，也计入该报价。
3. 后续采样按原数量检查反向退出；预期整个往返收益达到 `--cycle-target-bps 2` 才决定退出。
4. 退出同样使用延迟后的报价，因此实际影子结果可能达不到目标甚至亏损。
5. 达到 `--max-hold-seconds 3600` 后尝试按下一个有效探测强制退出，超时不表示保证在该秒能平仓。
6. 未平仓库存按可观测的反向退出成本估值；无法估值则留空并标记。影子净结果包含此估值。

**模型没有模拟成交概率、排队、自身市场冲击或真实单腿故障。** 延迟后有深度不代表原订单会成交。
未知执行观测单独计数；存在此类决策时标记“执行估算不完整”，不能进入正值候选。
模型不是实盘收益、不是完整账户回测，也不能拿这个胜率替代真实双腿成交率。

额外成本假设：

- `--reserve-bps 2`：每次跨市场的两腿合计额外成本准备，往返各扣一次；不是自动测量的滑点。
- `--holding-cost-bps-hour 0`：每小时持仓成本压力测试，按每次影子建仓名义额计算。
  默认 0 **不表示资金费实际为 0**。真实资金费未采集，网页始终提示。
- 公共元数据费率以百分数转换为 bps；有不同账户费率时，在采集时用
  `--rh-fee-bps`、`--lighter-fee-bps` 指定真实值。
- `--rh-quote-usd 1` 和 `--lighter-quote-usd 1` 是固定换算假设，抵押品偏离 1 美元时应调整。

应比较多个成本准备和持有时限情景，而不是只选出最好看的一个参数组合。
收益集中度是最盈利小时占全部正的影子往返收益之比；采样最大回撤会遗漏采样之间的价格极值。
分位数采用固定随机种子的最多 10,000 个观测蓄水池；大样本时为近似值。
累计金额、周期数和胜负计数为完整累计；网页只保留最近 2,000 个周期详情，CSV 保存全部周期。

## 有限测试与正式采集

先做 2 分钟连通性检查：

```bash
python3 tools/market_screener.py collect --symbols SNDK,ANTHROPIC --hours 0.0334
```

然后正式运行全市场 72 小时。不要把连通性测试产生的“训练不足”当成错误。
停止后换服务器会产生新会话，分析不自动混合不同服务器的数据。
